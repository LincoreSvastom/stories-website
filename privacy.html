2. This website and its hosting

The prepared website is static HTML and CSS. It has no account system, upload form, first-party analytics, advertising scripts, embedded social players, or application token storage. The website does not process or host your desktop videos.

When published on GitHub Pages, GitHub processes hosting request data, including visitor IP addresses for security. This is separate from Stories desktop storage; do not interpret the absence of first-party analytics as an absence of hosting logs. See the GitHub Privacy Statement.

Following an external link opens a third-party service governed by its own practices. The current static pages do not set first-party cookies or use browser local storage.

3. Local media and application data

Video splitting, trimming, framing and text-overlay rendering run on your computer through FFmpeg. Inputs, exported clips, previews and optional local speech transcripts are stored on your device in folders you select or in application-managed storage. Optional speech recognition may download model files from third-party model hosts; recognition itself is performed locally by the current implementation.

The application keeps settings and a local SQLite queue. Queue records can include file paths, story titles, episode numbers, titles, descriptions, hashtags, file fingerprints, visibility, schedules, status, errors, attempts, platform IDs and returned video URLs. Full SHA-256 fingerprints support duplicate detection in the desktop workflow.

Desktop-managed data normally resides in %LOCALAPPDATA%\RedditTikTokStudio, or an explicitly selected data directory. The legacy command-line version can store data within its project directory. User-selected output folders can be elsewhere.

4. Account authorization and tokens

The application uses official TikTok and Google/YouTube OAuth flows. You sign in with the platform in your browser; Stories does not ask for your TikTok or Google account password. Authorization requests use a local loopback callback in the desktop application. This website is not that callback and does not exchange authorization codes.

Access tokens, refresh tokens, scopes, expiry information and platform identifiers returned during authorization are saved through the operating-system credential vault using keyring. On Windows this relies on the configured Windows credential backend. Tokens are not intentionally stored in the website or the publication database.

The current desktop TikTok setup uses developer-supplied client credentials in process/environment configuration. The GUI does not persist the entered TikTok client secret in its settings file. Do not put a client secret or token in this website, a public repository, a screenshot or a support message.

Supported refresh operations contact the relevant platform to renew access. Refreshing access and checking publication status can create network requests even when no new video is being uploaded.

5. What reaches TikTok and YouTube

The desktop application uses YouTube API Services. Google authorization requests upload permission and read permission used for channel information and processing/visibility checks. The application may receive the channel title, video ID, processing status, visibility and API error information.

TikTok authorization requests user.info.basic together with the selected posting permission: video.upload for Inbox or video.publish for eligible Direct Post. Actual access is limited to permissions approved for the app and granted by the user. Token responses can contain account identifiers, scopes and expiry data. Direct Post queries creator information, including allowed posting settings. The current implementation does not separately fetch a full profile through the User Info endpoint.

When you explicitly authorize an upload or enable an already-consented schedule, the selected video bytes and relevant posting metadata are sent directly from your computer to the platform API or its returned upload endpoint. This may include the title, description, hashtags, visibility and other supported post settings. TikTok Inbox upload requires further review and completion in TikTok. Uploading does not guarantee publication or public visibility.

Platform processing is governed separately by the TikTok Privacy Policy and Google Privacy Policy. Authorization, review, quotas and account restrictions remain under the platform's control.

6. Retention, backups and diagnostics

Local queue history, settings, previews, transcripts, model files and exported media do not have a universal automatic deletion deadline in the current application. They remain until you remove them, choose different storage or overwrite data through a supported action. Previous rendered generations can be archived rather than deleted.

Desktop queue backups are created daily on application startup and on manual request; schema migration can create an additional backup. Backups contain private queue metadata, are not encrypted by Stories, and are not automatically removed. Deleting a live database does not delete its backups. Token-vault entries are separate from these database backups.

Local logs rotate by size and can include file names, paths and error details. The implementation redacts recognized secret patterns, but you should still inspect any material before sharing it. Optional diagnostic export contains application/runtime version and task-count information, not videos, database contents, configuration, raw logs or tokens. Exporting a ZIP locally does not automatically send it to the developer.

If you later contact the operator, your message and reply details may be processed to handle that request. Messages to this Gmail address are handled using Google's email service. No response-time or automatic erasure service is promised.

7. Your controls, deletion and rights

You can choose which files to process, deny optional platform permissions, leave the sender disabled, stop new queue submissions and revoke account access in the platform's account settings. Do not force-delete data during an active upload: the result can become uncertain and needs manual verification before retrying.

  • Google/YouTube: revoke access at Google Account third-party connections. This does not by itself delete videos already stored on YouTube.
  • TikTok: remove Stories access using TikTok's connected-app/account permission settings. This website has no remote revocation or deletion endpoint.
  • Device data: close the application, then remove the selected local data, outputs, previews and backups you no longer need. Retain anything required for upload reconciliation.
  • Saved tokens: remove the application's credential-vault entries through the operating-system credential manager. Removing AppData or uninstalling the app does not necessarily remove these separate entries.
  • Platform posts: manage or delete published content directly on the relevant platform; deleting a local queue record does not delete a remote post.

For operator-held correspondence, questions or requests concerning applicable access, correction or deletion rights, use the public privacy contact listed below. The operator does not acquire access to your local files merely because the application is installed. No automated website data-deletion mechanism is represented.

8. Security and changes

Local processing reduces unnecessary transfer of source media, but no software, device or credential store can be guaranteed completely secure. Keep your Windows account protected and use encrypted storage where appropriate. External APIs use HTTPS; the desktop loopback callback uses local HTTP.

Account and platform services may process information outside your country under their own policies. This policy does not claim certification, a platform endorsement, or a particular international-transfer mechanism for Stories.

Any material change to the actual application data flows should be reflected in this policy. The updated document will show a revised date. Mandatory rights under applicable law are not waived by this policy.
